# CourseLoop 可运行系统与部署说明

线上核对日期：2026-10-09 UTC。线上采用c171ac5基线及视觉接入版本；提交版包含并发、查询优化和独立演示服务器，并已完成隔离验收。环境对应关系见 [README环境表](../../README.md)。本次材料修订保持线上服务不变，v1.0提供4810题处理后内容与2646块FTS，见[数据清单](processed-data-inventory.json)。

## 一、系统访问

本地入口：`http://127.0.0.1:8000/`，启动命令见下文。本地多角色演示账号见 [ACCESS.md](../../ACCESS.md)。线上体验地址与评审凭据通过比赛指定渠道单独提供，不随公开材料分发。

系统采用前后端分离架构，本地运行包提供同源访问方式。公开 /api/health 只报告存活与模型状态；版本、模型、检索就绪信息放在管理员 /admin/runtime，完整配置由部署者独立管理。

评委账号只应填写虚构学习信息。线上操作会留下该账号的测试学习记录；生产中的其他账号、原密码与学生资料不随交付分发。教师复核、开课、资料上传和停用账号等写操作请在本地或隔离测试环境演示。

## 二、环境依赖

Python 3.10+，验证环境为 Python 3.10.20；Node 20.19+ 或 22.12+，npm；Linux 的 SQLite 需支持 FTS5 trigram。无需 GPU、torch、Chroma 或本地大模型即可启动原创轻量演示。基础建议 2 核、4 GB，磁盘预留 2 GB；容量评价以05报告所列环境与实测为依据。

运行依赖用 requirements.txt 锁定；requirements-submission.lock.txt 记录轻量验证环境（包含测试与审计工具）。requirements-research.txt 提供可选向量依赖；requirements-gpu-submission.txt固定4090D推理依赖，GPU和应用完整环境锁见artifacts/evidence/v1.0/gpu-4090d/。训练环境按07扩展协议单独验证。

## 三、从源码部署：无卡、无密钥基础模式

```bash
git clone https://github.com/cccccrj/courseloop-competition-submission.git
cd courseloop-competition-submission
git checkout v1.0
python3 -m venv .venv
.venv/bin/python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt
.venv/bin/python scripts/submission_prepare.py bootstrap
cd frontend
npm ci
npm run build
cd ..
.venv/bin/python -m uvicorn scripts.submission_serve:app --host 127.0.0.1 --port 8000 --workers 1
```

访问 http://127.0.0.1:8000/，用 ACCESS.md 的账号登录。bootstrap 仅在没有业务库的全新目录执行，生成 36 道题、四课程大纲、4 份原创讲义、5 个比赛账号与明确标注的合成错题示例；遇已有库拒绝覆盖。不能拿旧 seed_problems 当日常增量迁移：该旧脚本会清空数据结构题库。

演示服务同源代理 /api，提供前端 SPA。只监听回环地址。远程体验可用 SSH -L 8000:127.0.0.1:8000 或自行配置 HTTPS Nginx；不要直接把带弱密码 demo 账号的开发服务暴露公网。

## 四、运行包与开发模式

Release 运行包含源码、编译后的frontend/dist、完整处理后内容库及检索索引、正式报告和SHA-256校验值。校验解压后新建虚拟环境并安装requirements.txt，直接启动submission_serve即可；bootstrap用于独立的新建轻量演示目录。

[v1.0 Release](https://github.com/cccccrj/courseloop-competition-submission/releases/tag/v1.0)的校验、解压及启动命令见 [README运行包操作](../../README.md#release-运行包)。压缩包顶层目录为`courseloop-submission/`，安装与启动均在该目录执行；随包内容库可直接使用，bootstrap用于独立的新建轻量演示目录。

开发前端可分别启动：后端 uvicorn backend.api.main:app 监听 127.0.0.1:8000；frontend 中 npm run dev，打开 http://localhost:6006。CL_BACKEND_URL 控制开发代理目标，默认 http://127.0.0.1:8000；CL_ALLOWED_HOSTS 控制允许开发域名。正式部署按 [部署模板](../../deploy/)配置绝对路径、域名和端口。

## 五、开启真实模型

编辑仅本地的.env，设置CL_LLM_BASE_URL、CL_LLM_API_KEY、CL_LLM_WORKHORSE_MODEL；按需要配置expert和reasoner。视觉独立设置CL_LLM_VISION_BASE_URL=https://api.zhizengzeng.com/v1、CL_LLM_VISION_API_KEY为自己的私有凭据、CL_LLM_VISION_MODEL=qwen3-vl-30b-a3b-instruct、CL_LLM_VISION_TEMPERATURE=0.0，不覆盖现有文本模型配置。采用OpenAI兼容接口。CL_RAG_MODE=fts5与CL_RAG_FTS_PATH指向演示索引；设置独立CL_SECRET_KEY后重启服务。不得把线上.env复制进代码仓库。

在线演示服务已配置视觉模型，健康检查视觉就绪，且真实图片转写与公网拍照批改 SSE 流程实测通过，证据见 artifacts/evidence/v1.0/vision-live.json。下载包采用独立凭据配置，自行部署时填写自己的视觉服务密钥；公网模型模式与本地无密钥基础模式分别提供对应体验。

配置模型后，讲解、诊断、生成练习和周报点评按供应商计费，并把题干、图片或用户输入发送给服务商。输入应使用虚构身份和获授权资料。自行部署完成视觉配置后开启图片处理，文本就绪与视觉就绪可分别通过健康检查确认；外部API模式需要网络连接，无密钥基础模式支持本地确定性功能。

## 六、独立GPU部署

4090D部署采用本仓库提交版及36题／4讲义原创演示库，与在线演示环境隔离。现有Qwen3-14B-FP8与courseloop-408 LoRA通过本地vLLM提供文本推理；应用与GPU依赖分别放入独立虚拟环境。部署脚本、模型目录、实测参数和完整复现说明见08报告；模型权重按授权在部署服务器独立保管，不进入Git。

应用仅监听127.0.0.1:18080，模型仅监听127.0.0.1:18003。授权用户通过SSH端口转发访问应用，本地登录使用ACCESS.md中的演示账号，不分发服务器管理员口令。公网视觉API仍由测试环境线上服务提供，GPU实验单独验证文本推理与教学协同。

## 七、验收与运维

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m scripts.smoke_demo_path --out artifacts/evidence/demo-smoke.json
.venv/bin/python scripts/submission_algorithms.py --out artifacts/evidence/algorithms.json
cd frontend && npm run type-check && npm run build
```

测试环境压力与协同写入测试只能用独立目录、独立 SQLite、独立令牌密钥；不要把 submission_isolate 或 load 用于生产。备份业务库应采用 SQLite backup API，不能只复制正在写的 .db 而忽略 WAL。复习、会话及阅卷数据与库一并备份。线上赛后由管理员停用比赛账号；交付程序不会自动改变线上账号状态。
