# CourseLoop 正式提交版本测试报告

正式交付版本：v1.0。本报告组织已完成的业务容量、GPU实测与完整处理后内容验收，统一证据目录为artifacts/evidence/v1.0/，完整内容验收见[processed-data](../../artifacts/evidence/v1.0/processed-data/)。各实验保留实际源码快照、时间、输入规模与设备条件；交付编号统一不表示重新测量。提交版并发优化通过独立测试验证，视觉链路按专项API实验评价；在线演示与本地运行包分别提供功能体验和可复现部署。

## 一、环境与实验设计

公开交付整理验证：本轮源码回归628项通过；处理后运行副本86项功能检查通过，100次同账号并发记录完整、掌握度一致，四课程检索通过。本地演示密码已与线上凭据分离，22张非身份表逐行保持一致。部署信息与凭据扫描覆盖源码、正式报告、图像及发布附件；冻结版本的核验摘要见Release中的RELEASE-VALIDATION.json。历史容量与GPU指标继续按原实验条件呈现。

测试环境容量实验使用4808题、2646检索块，只使用虚构账号、独立数据库和签名密钥。并发阶段的业务代码保持不变；功能、同账号、10/25/50用户测试串行运行。视觉路由及转写另行进行真实API验收，不影响混合业务压测模块。v1.0下载包提供4810题／2646块；原创轻量部署与GPU实验使用36题／4讲义演示数据。

新增GPU交付工具的源码回归在独立云服务器应用环境执行：Python3.10.15，604项通过，见JUnit及完整日志。GPU性能与该服务器功能、浏览器、真实问答链路按08专项报告列示；业务并发模块与测试环境最终压测源码一致。

单Uvicorn worker；20%确定性单选判题写入、80%业务读取；每用户思考0.1秒。10人60秒、25人120秒、50人1800秒。预设标准：错误率≤1%、整体P95≤2000ms、逐账号写入全部对账、DB quick_check=ok。本组实验验证CPU与数据库业务链路，采用所列负载和单worker配置；LLM生成吞吐、最大容量与多机性能分别通过专项实验评价。

## 四、同账号并发与事务正确性

5轮，每轮新虚构身份、初始掌握度0.2618、10客户端提交20次正确答案。总100次请求；每轮新增20条记录，并将实际掌握度与逐次串行算法值比较，避免掌握度饱和掩盖错误。结果：记录完整=True，掌握度一致=True。逐轮预期/实际值见same-user-final.json。

源码回归覆盖多线程及独立进程累积、题库与旧Tutor会话交叉写入、故障注入整事务回滚、嵌套保存点、幂等索引迁移、连接并行上限、写者独立通道，以及同步请求连接复用、线程隔离和异常后恢复。故障注入属于主动健壮性测试，用于验证事务回滚与恢复行为。
